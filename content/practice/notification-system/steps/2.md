List the **entities** with kind (class / interface / enum / value object), key fields and responsibility.

Pay attention to the difference between a **notification** (what the caller asked for) and a **delivery** (one channel's attempt history).

<!-- answer -->

## Request and delivery

| Entity | Kind | Holds |
|---|---|---|
| `Notification` | value object (built with a **Builder**) | idempotencyKey, userId, templateId, category, priority, params, channels, scheduledAt |
| `Channel` | enum | `EMAIL`, `SMS`, `PUSH`, `IN_APP` |
| `Priority` | enum | `CRITICAL` (OTP), `HIGH` (transactional), `LOW` (marketing) |
| `Delivery` | class | notificationId, channel, status, attempts, lastError, providerMessageId |
| `DeliveryStatus` | enum (state machine) | `PENDING → SENDING → SENT → DELIVERED`, `FAILED`, `SKIPPED` |

One notification fans out to **N deliveries**, one per channel. Each has its own status and retries. SMS may fail while email succeeds.

## Content

| Entity | Responsibility |
|---|---|
| `Template` | text per (templateId, channel, locale) with `{{placeholders}}` |
| `TemplateStore` / `Renderer` | look up and render with params |

## Users

| Entity | Responsibility |
|---|---|
| `UserPreferences` | addresses (email, phone, device tokens), opted-out channels, muted categories, quiet hours, timezone |
| `PreferenceStore` | interface for loading preferences |

## Delivery machinery

| Entity | Kind | Responsibility |
|---|---|---|
| `ChannelSender` | interface (**Strategy/Adapter**) | `send(message)`, implemented by `SesEmailSender`, `TwilioSmsSender`, `FcmPushSender`, `InAppSender` |
| `DeliveryFilter` | interface (**Chain of Responsibility**) | `PreferenceFilter`, `QuietHoursFilter`, `RateLimitFilter` |
| `RetryPolicy` | value object | max attempts, base delay, jitter |
| `NotificationQueue` | interface | priority queues, delayed retry |
| `NotificationService` | facade | accept, dedupe, enqueue, and run workers |
| `DeliveryListener` | interface (**Observer**) | status changes go to the status store, metrics and webhooks back to callers |
