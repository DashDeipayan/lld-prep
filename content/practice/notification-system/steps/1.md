The interviewer said: *"Design a notification system. Other services should be able to notify users by email, SMS, push or in-app."*

Write down:
1. The **questions** you'd ask (aim for 6–10).
2. The **functional requirements** you'd agree on.
3. **Non-functional** requirements.
4. **Out of scope**.

## Questions worth asking

- Who calls us, and with what? *(internal services send `event + userId + templateId + params`, not raw text)*
- Which channels? *(email, SMS, push, in-app, with more later)*
- Do users control what they get? *(yes: per-channel and per-category opt-out, plus quiet hours)*
- Are all notifications equal? *(no: **transactional** (OTP, payment) is high priority, **marketing** is low)*
- Synchronous or async? *(callers get an id back immediately, and delivery is async)*
- What if a provider fails? *(retry transient errors with backoff, then mark failed. Failover is a follow-up.)*
- Can a caller accidentally send twice? *(yes, they retry on timeouts, so we must **dedupe**)*
- Do we track delivery? *(status per channel: pending, sent, delivered, failed)*
- Rate limits? *(cap marketing per user per day, and respect provider quotas)*
- Localisation? *(templates per locale, which can be mentioned briefly)*

## Functional requirements

1. `send(request) → notificationId`, where the request has an idempotency key, userId, templateId, category, params and channels.
2. Render a **template** per channel (`"Hi {{name}}, order {{orderId}} shipped"`).
3. Respect **preferences**: channel opt-outs, muted categories, quiet hours (except critical).
4. Deliver through **channel providers**, retrying transient failures with exponential backoff.
5. **Dedupe** requests with the same idempotency key.
6. Track and expose **delivery status** per channel. In-app notifications are listable per user.

## Non-functional

- At-least-once delivery for transactional messages and **no duplicates** visible to users (idempotency).
- OTPs delivered within seconds even during a marketing blast (**priority isolation**).
- Extensible: a new channel or provider without touching the core.

## Out of scope

The providers themselves, campaign/segmentation tooling, analytics dashboards, the email HTML designer.
