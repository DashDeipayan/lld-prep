Write the `assess(txn)` algorithm. Decide and justify:

1. How a rule's output combines **hard blocks** and **scores**.
2. How the final decision is made.
3. Rule **ordering** and **short-circuiting**.
4. What happens when a rule **throws or times out**.

Walk through one example: a ₹2,00,000 payment from a new device in a different country, with thresholds REVIEW ≥ 50, BLOCK ≥ 80.

## Algorithm

```
assess(txn, ctx):
  ruleSet = config.get()                 // one consistent snapshot
  score = 0; hard = ALLOW; hits = []
  for rule in ruleSet.rules:             // cheap, decisive rules first
    try
      r = rule.evaluate(txn, ctx)        // with a per-rule time budget
    catch error / timeout
      r = RuleResult(rule.id, 0, REVIEW, "rule error")   // fail safe, never silent
    if r.triggered:
      hits.add(r)
      score += r.score
      hard = max(hard, r.verdict)
      if hard == BLOCK: break            // nothing can make it less severe
  decision = max(ruleSet.policy.decide(score), hard)
  a = Assessment(txn.id, decision, score, hits, ruleSet.version)
  notify listeners(a)                    // audit, review queue, alerts
  return a
```

## Design decisions

- **Two channels per rule.** A `verdict` for "this alone decides" (blocklist → BLOCK) and a `score` for "this adds suspicion" (new device +30). Most real engines need both.
- **`Decision` is ordered** (`ALLOW < REVIEW < BLOCK`), so combining is just `max`. No `if/else` ladder.
- **Order**: list lookups and hard rules first (cheap and decisive), then scoring rules, then expensive ones (an external ML score, device fingerprinting). Short-circuit only on BLOCK, since nothing can lower it.
- **Failure.** Fail open (allow) loses money silently, and fail closed (block) hurts good customers. **REVIEW** plus an alert is the usual middle ground. Say it's a business decision and make it configurable per rule.

## The example

| Rule | Result |
|---|---|
| blocklist | pass |
| large-amount (> ₹1,00,000) | +40 |
| new-device | +30 |
| country-mismatch | +25 |

Total **95 ≥ 80 → BLOCK**, with three reasons in the audit log. Remove the country mismatch and the total is 70, which gives REVIEW and a review case.

> **Explainability matters.** Support and regulators will ask *"why was this blocked?"*. Keeping every `RuleResult` with its reason and the config version answers that.
