List the **entities**. For each: class, interface, enum or value object; its fields; its responsibility.

Make sure you separate *what's suspicious* from *what we do about it*.

<!-- answer -->

## Inputs

| Entity | Kind | Holds |
|---|---|---|
| `Transaction` | value object | id, userId, amount (minor units), currency, merchant, country, deviceId, ip, timestamp |
| `UserProfile` / `RiskContext` | value object | home country, known devices, account age (enrichment loaded once per assessment) |

## Logic

| Entity | Kind | Responsibility |
|---|---|---|
| `Rule` | interface (**Strategy**) | `evaluate(txn, ctx) → RuleResult` |
| `LargeAmountRule`, `VelocityRule`, `BlocklistRule`, `NewDeviceRule`, `CountryMismatchRule` | classes | one check each |
| `DecisionPolicy` | interface (Strategy) | `decide(score) → Decision`, e.g. `ThresholdPolicy(reviewAt, blockAt)` |
| `RiskEngine` | class (facade) | runs the rules, combines results, notifies listeners |
| `RuleFactory` / `RuleRegistry` | class (**Factory**) | builds `Rule` objects from config (`{"type":"velocity","max":5,"window":"10m"}`) |

## State

| Entity | Responsibility |
|---|---|
| `VelocityStore` | sliding-window counts per key (`velocity:user:u1`) |
| `ListStore` | blocklists and allowlists |

Rules are **stateless logic**. State lives in stores the rules are given, which keeps rules easy to test and lets the store move to Redis later.

## Outputs

| Entity | Kind | Holds |
|---|---|---|
| `Decision` | enum, ordered | `ALLOW < REVIEW < BLOCK` |
| `RuleResult` | value object | ruleId, score, verdict (hard decision or ALLOW), reason |
| `Assessment` | value object | txnId, decision, total score, triggered rule results, config version |
| `DecisionListener` | interface (**Observer**) | `AuditLog`, `ReviewQueue`, `AlertNotifier` |

> **Key separation:** rules say *what's suspicious* (with a score and reason), and the policy says *what we do about it*. Analysts tune thresholds daily without touching rule code.
