Rule: *"Flag a user who makes more than 5 transactions within any 10-minute window."*

1. What exactly do you store per user, and how do you evaluate the rule?
2. Compare at least **two** windowing approaches on accuracy and memory.
3. Should a **blocked** transaction count towards velocity? A **declined-by-bank** one?

## Sliding-window log (exact)

Per key (`velocity:user:u1`), keep a deque of timestamps:

```
recordAndCount(key, at, window):
  q = events[key]
  q.append(at)
  while q.front <= at - window: q.popFront()     // evict old events
  return len(q)
```

The rule triggers when `count > max`. Each call is amortised O(1). Memory is O(events in the window) per key.

## Alternatives

| Approach | How | Accuracy | Memory |
|---|---|---|---|
| **Fixed window** | counter per `floor(t / 10min)` | Bursty at the edges: 5 at 10:09 and 5 at 10:10 both pass | O(1) per key |
| **Sliding log** *(above)* | deque of timestamps | exact | O(N) per key |
| **Sliding buckets** | e.g. 10 one-minute buckets in a ring, sum them | close (1-minute granularity) | O(buckets) per key |

For per-user payment velocity (small N), the **sliding log** is the right choice. For per-IP or per-merchant keys with thousands of events per window, use **buckets**. In Redis, the log becomes a sorted set (`ZADD` / `ZREMRANGEBYSCORE` / `ZCARD` in one Lua script) and buckets become `INCR` with `EXPIRE`.

## Keys and variants

- Count **and** amount: "more than ₹50,000 total in 1 hour" stores `(timestamp, amount)` pairs and sums them.
- Many dimensions: per user, per card, per device, per IP, per merchant. It's the same rule class with a different `keyFn`.

## What counts?

- **Count attempts, not just approvals.** Card-testing fraud is many *failed* attempts, and only counting approvals hides it.
- If a hard rule short-circuits before the velocity rule runs, that attempt **isn't recorded**. Either run velocity recording before the short-circuit, or record attempts in a listener on every assessment. Mention it. It's the kind of subtle bug interviewers like you to find.
