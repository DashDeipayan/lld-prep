## Catalog side (what exists)

| Entity | Kind | Holds |
|---|---|---|
| `Song` | value object | id, title, artist, album, durationSec |
| `Artist`, `Album` | classes | name, songs (album: ordered tracks) |
| `Playlist` | class | id, name, owner, `List<Song>` (ordered, duplicates allowed) |
| `Library` | class | songs, albums, playlists, plus lookup and search |

## Playback side (what's happening now)

| Entity | Kind | Responsibility |
|---|---|---|
| `PlayQueue` | class | songs loaded for playback, **play order**, cursor, shuffle |
| `RepeatMode` | enum | `OFF`, `ONE`, `ALL` |
| `PlayerState` | interface (State pattern) | `Stopped`, `Playing`, `Paused` |
| `Player` | class (context, facade) | holds state, queue and repeat mode, and exposes the buttons |
| `AudioOutput` | interface (Adapter target) | `start(song)`, `prepare(song, atSec)`, `pause()`, `resume()`, `stop()`, `positionSec()` |
| `SpeakerOutput`, `BluetoothOutput`, `CastOutput` | classes (adapters) | each wraps one vendor SDK and translates it to `AudioOutput` |
| `AudioDevice` | value object | id, display name, `DeviceType` |
| `DeviceType` | enum | `SPEAKER`, `WIRED`, `BLUETOOTH`, `CAST` |
| `DeviceManager` | class | connected devices and their adapters, the active device, the speaker fallback |
| `PlayerListener` | interface (Observer) | `onSongChanged`, `onStateChanged` |

## Playlist ≠ queue

A **playlist** is saved catalog data. A **queue** is a temporary playback session built *from* a playlist, album or search result. Shuffling, "play next" and "add to queue" change the queue, **never the user's playlist**. Merging the two is the most common mistake on this problem: shuffle would reorder the user's saved playlist.

## Device ≠ output

`AudioDevice` is the **data** the device picker shows ("Living-room TV", CAST). `AudioOutput` is the **behaviour** the player calls. The `DeviceManager` maps one to the other. Keeping them apart means the picker UI never touches a vendor SDK, and the player never knows which kind of device it is talking to.
