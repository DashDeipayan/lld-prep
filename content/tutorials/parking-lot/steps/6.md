There are four entry gates, each a thread or goroutine, calling `park` at the same moment. Right now two gates can pick the same free spot. That's the check-then-act race from Day 5.

## The test

32 vehicles park **concurrently** into a lot with 20 spots. Exactly 20 must succeed, on **20 different spots**, and the other 12 must fail with *lot full*.

## Options (say them in the interview)

1. **One lock around park/unpark.** Simplest and obviously correct, and the critical section is microseconds. This is the right answer for one lot.
2. Lock per floor, or per size bucket. More throughput, but more complexity (what if floor 1 is full?).
3. CAS on each spot's state (`AtomicReference<Vehicle>`, `atomic.Pointer`). Lock-free, but you need retries when you lose the race.

Go with option 1. Keep the critical section tight, and fire listener events **after** releasing the lock.

```java
Ticket park(Vehicle v) {
    Ticket t; Event e;
    synchronized (this) {
        // ...the existing logic...
    }
    notifyListeners(e);   // outside the lock
    return t;
}
```

```go
func (l *ParkingLot) Park(v Vehicle) (*Ticket, error) {
	l.mu.Lock()
	t, ev, err := l.parkLocked(v)
	l.mu.Unlock()
	if err != nil {
		return nil, err
	}
	l.emit(ev) // outside the lock
	return t, nil
}
```

`available()` must also read under the lock. Copy the listener list under the lock (or use `CopyOnWriteArrayList`) before notifying.
