Now the lot itself. Floors are added at setup time:

```java
lot.addFloor(1, 2, 3, 1);   // floor 1: 2 small, 3 medium, 1 large
```

## Spot ids

Generate readable ids, because interviewers like seeing a ticket that says where the car is: `F<floor>-<S|M|L><n>`, numbered from 1 per size per floor.

`addFloor(1, 2, 3, 1)` creates `F1-S1 F1-S2 F1-M1 F1-M2 F1-M3 F1-L1`, in that order.

## Store spots in "lot order"

Keep one list of all spots, ordered by **floor (as added), then size S → M → L, then number**. That order is exactly what "nearest first" means, and it's what the selector strategy will receive in step 3.

Also keep a `Map<spotId, Spot>` for O(1) lookup on unpark.

## Availability

`available(size)` returns the number of **free** spots of that size across all floors. Adding the same floor number twice is invalid (Java `IllegalArgumentException`, Go `ErrDuplicateFloor`).

```java
int available(SpotSize size) {
    int n = 0;
    for (Spot s : spots) if (s.size() == size && s.isFree()) n++;
    return n;
}
```

This is O(spots), which is fine for an interview. Mention that you could keep counters per size if `available` were hot. You'll effectively do that with the display board in step 5.
