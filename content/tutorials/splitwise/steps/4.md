`settle(from, to, amount)` records that `from` paid `to` back.

- Both users must exist, and `amount > 0`.
- `amount` must not exceed `owes(from, to)`. Overpaying would make the receiver owe the payer, which is confusing UX, so reject it (Java `IllegalStateException`, Go `ErrOverSettle`, Python the provided `SettlementError`).
- Effect: `addDebt(to, from, amount)`. That's a debt in the opposite direction, which reduces `from`'s debt.

Look how little code that is. The netting model from step 3 makes settlement the **same operation** as an expense. Point this out in the interview: good data modelling makes features cheap.
